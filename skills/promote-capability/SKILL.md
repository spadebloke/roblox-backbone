# Promote capability

Use only for demonstrated cross-project value.

1. Identify the project-local capability and evidence that it is generic.
2. Remove game-specific assumptions.
3. Choose the lightest reusable form: doc, skill, script, Luau module, or external integration.
4. Estimate recurring context and maintenance cost.
5. Add focused tests or deterministic validation where applicable.
6. Document adoption without forcing unrelated projects to use it.
7. Keep project-specific history out of the backbone.

If a capability cannot remain optional and locally understandable, reconsider promotion.
